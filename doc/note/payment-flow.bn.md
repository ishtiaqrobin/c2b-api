# পেমেন্ট সিস্টেম — কাস্টমারের অর্ডার দেওয়ার পর কখন ও কীভাবে পেমেন্ট সম্পন্ন হয়

এই ডকুমেন্টে বর্ণনা করা হয়েছে: কাস্টমার (বিক্রেতা) অর্ডার জমা দেওয়ার পরে পেমেন্ট সিস্টেমটি **কখন** ও **কীভাবে** সম্পূর্ণ হয়।

---

## ১. সার্বিক ধারণা

এই প্ল্যাটফর্মটি **C2B (Customer-to-Business)** — অর্থাৎ কাস্টমার তার ব্যবহৃত পণ্য **বিজনেসের কাছে বিক্রি** করে। তাই "পেমেন্ট" বলতে এখানে **বিজনেসের পক্ষ থেকে কাস্টমারকে পণ্যের দাম পরিশোধ করা** বোঝায়।

- পেমেন্ট **ম্যানুয়ালি** পরিচালিত হয় (অনলাইন গেটওয়ে নেই)।
- অর্ডার **APPROVED** হওয়ার সাথে সাথেই পেমেন্ট রেকর্ড **স্বয়ংক্রিয়ভাবে** তৈরি হয়।
- অ্যাডমিন পেমেন্ট **PAID / FAILED / REFUNDED** চিহ্নিত করেন এবং অর্ডারের অবস্থাও সেই অনুযায়ী আপডেট হয়।
- কাস্টমার তার ড্যাশবোর্ড থেকে পেমেন্টের ইতিহাস দেখতে পারেন এবং টাকা পাওয়ার পদ্ধতি (বিকাশ/নগদ/ব্যাংক) আপডেট করতে পারেন।

---

## ২. অর্ডার → পেমেন্টের ধাপ (সময়-ভিত্তিক ফ্লো)

| ধাপ | সময়/শর্ত | কী ঘটে |
|----|-----------|--------|
| ১ | কাস্টমার অর্ডার জমা দেয় | অর্ডার তৈরি হয় (`PENDING` → পরবর্তীতে `SUBMITTED` ইত্যাদি) |
| ২ | পণ্য চেক/ইন্সপেকশন সম্পন্ন | স্টাফ মূল্য নির্ধারণ করে (PRICE_OFFERED) |
| ৩ | অর্ডার **APPROVED** হলে (একই মুহূর্তে) | **পেমেন্ট রেকর্ড অটো-তৈরি হয়** — অবস্থা `PENDING`, পরিমাণ = অর্ডারের `totalAmount` |
| ৪ | কাস্টমার পেআউট তথ্য দেয়/হালনাগাদ করে | বিকাশ নম্বর, নগদ নম্বর, ব্যাংক অ্যাকাউন্ট ইত্যাদি |
| ৫ | অ্যাডমিন টাকা পরিশোধ করেন | পেমেন্ট `PAID` চিহ্নিত হয় (পদ্ধতি + রেফারেন্স + নোটসহ) |
| ৬ | **সাথে সাথে** | অর্ডারের অবস্থা স্বয়ংক্রিয়ভাবে `PAID` হয় |
| ৭ | (ঐচ্ছিক) রিফান্ড | পেমেন্ট `REFUNDED` হলে অর্ডার `PAYMENT_PENDING`-এ ফিরে যায় |

## ৩. কখন পেমেন্ট তৈরি হয় (Auto-creation)

- পেমেন্ট **শুধুমাত্র অর্ডারের status `APPROVED` হওয়ার সময়** তৈরি হয়।
- `OrderService.updateOrderStatus`-এ এই লজিক ট্রানজেকশনের মধ্যে থাকে — অর্ডার আপডেট আর পেমেন্ট তৈরি একসাথে commit হয়।
- প্রতিটি অর্ডারে **একটিই** পেমেন্ট থাকতে পারে (একই অর্ডারে বারবার তৈরি হয় না — upsert ব্যবহার করা হয়েছে)।
- প্রাথমিক অবস্থা: `PENDING`
- প্রাথমিক পদ্ধতি: `CASH` (অ্যাডমিন পরে আপডেট করেন)
- পরিমাণ: অর্ডারের `totalAmount` (মুদ্রা: BDT)

## ৪. পেমেন্টের অবস্থা (Status) ও এর অর্থ

| Status | বাংলা অর্থ | অর্ডারে প্রভাব |
|--------|-----------|----------------|
| `PENDING` | অপেক্ষমান — টাকা এখনও দেওয়া হয়নি | অর্ডার `APPROVED` অবস্থায় থাকে |
| `PROCESSING` | প্রক্রিয়াধীন (ভবিষ্যতে গেটওয়ের জন্য সংরক্ষিত) | পরিবর্তন নেই |
| `PAID` | কাস্টমারকে টাকা পরিশোধ করা হয়েছে | **অর্ডার → `PAID`** |
| `FAILED` | পরিশোধ ব্যর্থ হয়েছে | অর্ডার `APPROVED`-এ থাকে (পুনরায় চেষ্টা করা যায়) |
| `REFUNDED` | টাকা ফেরত নেওয়া হয়েছে | **অর্ডার → `PAYMENT_PENDING`** |

> নোট: `PAID` → `REFUNDED` শুধুমাত্র সম্ভব। একবার `PAID` হলে পুনরায় `FAILED` করা যায় না।

## ৫. অ্যাডমিন কীভাবে পেমেন্ট সম্পন্ন করেন

1. অ্যাডমিন **`/admin-dashboard/payments`** পেজে যান।
2. পেমেন্ট তালিকা থেকে যেকোনো পেমেন্টের **Manage** বাটনে ক্লিক করেন।
3. ডিটেইল ডায়ালগে পেমেন্টের তথ্য দেখা যায়:
   - অর্ডার নম্বর, কাস্টমারের নাম/ইমেইল
   - কাস্টমারের পেআউট তথ্য (বিকাশ/নগদ/ব্যাংক)
   - বর্তমান অবস্থা, পরিমাণ, ইতিহাস (statusHistory)
4. **Mark as Paid** করতে গেলে:
   - নতুন অবস্থা: `PAID`
   - পদ্ধতি (`method`): `BKASH` / `NAGAD` / `ROCKET` / `BANK_TRANSFER` / `CASH`
   - রেফারেন্স (ট্রানজেকশন আইডি, যেমন "TRX12345")
   - নোট (ঐচ্ছিক)
5. Save করলে:
   - পেমেন্ট `PAID` + `paidAt` টাইমস্ট্যাম্প সেট হয়
   - `PaymentStatusHistory`-তে এন্ট্রি যোগ হয় (কে, কখন, কী থেকে কী)
   - **অর্ডার স্বয়ংক্রিয়ভাবে `PAID` হয়** এবং অর্ডারের `statusHistory`-তেও এন্ট্রি যোগ হয়

> প্রয়োজনীয় অনুমতি: **`payment.manage`** (SUPER_ADMIN / STORE_MANAGER / ORDER_MANAGER)

## ৬. কাস্টমার পক্ষ থেকে

- কাস্টমার **`/user-dashboard/payments`** পেজে নিজের সব পেমেন্ট দেখতে পান (অর্ডার নম্বর, অবস্থা, পরিমাণ, তারিখ)।
- পেআউট তথ্য (কোন পদ্ধতিতে টাকা নেবেন) আপডেট করতে পারেন:
  - পছন্দের পদ্ধতি: বিকাশ / নগদ / রকেট / ব্যাংক ট্রান্সফার / নগদ
  - বিকাশ নম্বর, নগদ নম্বর, ব্যাংকের নাম/শাখা/অ্যাকাউন্ট নম্বর
- অ্যাডমিন পেমেন্ট `PAID` করলে কাস্টমার পেজে সাথে সাথে দেখা যায়।

## ৭. API সংক্ষেপ

| Endpoint | পদ্ধতি | ব্যবহার |
|----------|--------|---------|
| `GET /api/v1/payments` | অ্যাডমিন | পেমেন্ট তালিকা (ফিল্টার: status, method, search; পেজিনেশন) |
| `GET /api/v1/payments/:id` | অ্যাডমিন | একক পেমেন্টের বিস্তারিত (অর্ডার + কাস্টমার + ইতিহাসসহ) |
| `PATCH /api/v1/payments/:id` | অ্যাডমিন | status/মেথড/রেফারেন্স/নোট আপডেট (PAID/FAILED/REFUNDED) |
| `GET /api/v1/payments/my` | কাস্টমার | নিজের পেমেন্ট ইতিহাস |
| `PATCH /api/v1/users/me/payout-info` | কাস্টমার | নিজের পেআউট তথ্য হালনাগাদ |

## ৮. উদাহরণ — সম্পূর্ণ ফ্লো (ধাপে ধাপে)

1. রাহিম একটি পুরনো ফোন বিক্রির অর্ডার দেয় → অর্ডার নম্বর `BB-2026-000007`।
2. ফোনটি স্টোরে পৌঁছালে স্টাফ মূল্য নির্ধারণ করে (১৫,০০০ টাকা)।
3. অ্যাডমিন অর্ডারটি **Approve** করেন → সাথে সাথে পেমেন্ট তৈরি হয়:
   - `amount: 15000`, `status: PENDING`, `method: CASH`
4. রাহিম তার পেমেন্ট পেজে গিয়ে পেআউট পদ্ধতি **বিকাশ (0171XXXXXXX)** সেট করে।
5. অ্যাডমিন `payments` পেজে গিয়ে পেমেন্ট **Manage** → Status `PAID`, মেথড `BKASH`, রেফারেন্স `TRX-7777` → Save।
6. রাহিমের বিকাশে ১৫,০০০ টাকা যায়; পেমেন্টের অবস্থা `PAID` এবং **অর্ডার `PAID`** হয়ে যায় — সব জায়গায় ইতিহাস সংরক্ষিত থাকে।
